# Domain docs

This is a single-context clinical-privacy repository.

Before domain-sensitive work read, as applicable:

- `CONTEXT.md` — canonical vocabulary, product boundaries and current system context;
- `docs/shaping/CURRENT_DECISIONS.md` — accepted durable product/architecture decisions;
- relevant `docs/specs/SPEC_V4_*.md` — behavioral contracts;
- relevant ADRs under `docs/adr/` if/when they exist.

Do not create a second glossary that silently diverges from `CONTEXT.md`. A dedicated `GLOSSARY.md` may be introduced later through explicit domain-modeling work if it replaces/moves vocabulary authority coherently.

Historical audits, retired specs, `odd/tasks/` and execution reports are evidence/provenance, not current domain authority unless a current ticket cites them.
