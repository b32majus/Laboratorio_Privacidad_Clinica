# Issue tracker: GitHub

Issues/specs/work orders for this repository live in GitHub Issues for `b32majus/Laboratorio_Privacidad_Clinica`.

Use `gh issue` / GitHub API from inside the clone. Read issue body, comments, blockers and labels before implementation; do not reconstruct accepted scope from chat or historical execution docs when current issue/spec authority exists.

A ticket is executable only when its current authority says it is ready and required blockers are resolved. Closing/labeling/creating issues is a remote mutation and follows the repository/human publication boundary.

Pull requests are delivery/review surfaces, not a general feature-request/triage queue.

Important branch fact: canonical V4 integration/deployment is `3.0-main`; the GitHub repository default branch remains `main` as of the C-083 reconciliation, so default-branch inference is unsafe for V4 work.
