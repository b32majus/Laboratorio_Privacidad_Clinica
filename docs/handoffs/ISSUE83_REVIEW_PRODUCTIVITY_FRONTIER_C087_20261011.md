## CLOSED PRODUCT DECISIONS — do not rediscover
1. **Entry / current context:** On first entry for a current session with pending detections, expose the earliest pending in canonical document order as the current *visible* decision, with source/context and its untouched pending status; no automatic decision. Preserve explicit current selection during ordinary rerenders and after a decision. Changing Job/batch active document/structured cell must not carry over old selection, drafts, confirmation or keyboard target, even if IDs/text repeat. When zero pending, say so factually; offer accessible previously decided items/correction, not a phantom next item.
2. **Navigation:** `Anterior pendiente` / `Siguiente pendiente` move in canonical source order between pending items, independent of a narrowing visual filter. The current filter stays unchanged; a selected pending item hidden by it must remain visible in the current inspector and source, with an accessible path back to the complete list. At boundaries, disable the respective command with intelligible state; **no implicit wrap**. Prev/next are explicit navigation only, zero ReviewSession mutation. Before any entity change by next/previous, document or list, an unsaved replacement/note draft **blocks** the transition with a local Spanish explanation and explicit **Descartar borrador** action. No modal and no implicit discard: the user can remain/edit/submit the current draft, or explicitly discard only its transient fields, then activate navigation again. The original session/other decisions remain unchanged. Existing completed ReviewSession notes are not drafts and must not block navigation. Preserve the accepted #81 manual-marking context and #82 keep-original confirmation routes.
3. **After decisions:** A successful Accept/Modify/Keep-original decision stays on that item, shows its factual resulting status and keeps correction/revisit available; a visible `Siguiente pendiente` route remains. **No auto-next and no bulk acceptance.** Failure never advances or discards typed replacement/note. The #82 Keep-original action must still invoke its exact contextual confirmation on direct/uncertain identifiers; Cancel remains zero-mutation. The user's filter and unrelated decisions are conserved.
4. **Keyboard contract:** Discoverable, closable Spanish shortcut help next to work. `A` invokes the existing explicit Accept only for the *current* selected entity; `M` focuses the replacement editor without submitting modification; `K` starts existing keep-original flow including mandatory #82 confirmation; `F` runs existing #81 `Marcar dato no detectado` **only with valid original-text selection**; `Alt+ArrowDown` / `Alt+ArrowUp` navigate next/previous pending. Key handling is scoped to Review, no global hotkeys, no modifier surprise or browser navigation conflicts. No shortcuts while typing in any input/textarea/select/contenteditable, during IME, within active manual/keep-original confirmation or when focus is outside Review. Visible buttons continue to work with native Tab/Enter/Space. Keyboard help enumerates actual working commands; do not hijack ordinary typing.
5. **Spatial/task hierarchy:** At 375×800 and 1280×800, the first meaningful Review state must expose the active pending decision, its context and next action without scrolling through a metrics dashboard or an entire 24-item list. Keep original text readable, discoverable and selectable for manual marking. The current decision/navigation/feedback are reachable together on mobile. Use existing workspace and responsive components; do not create a new page, separate navigation system, floating action bar, or global layout redesign. All newly touched labels/actions/errors are professional Spanish. Old unrelated English copy remains REC-10 debt.
6. **Bulk evaluation:** Explicitly **do not introduce grouped/bulk confirmation in #83**. Record this as a bounded evaluation of the issue's optional clause, not a permanent ban or an unimplemented mandatory feature.
